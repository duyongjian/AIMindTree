## 1. 产品定位与目标用户（源自 `docs/PRD.md`）

### 1.1 一句话定位

> 你只管写笔记，AI 负责把笔记拆成知识点、补全「要懂这个你得先懂什么」的前置路径、当老师考你；你的每一次追问都会变成一张贴在画布上的小卡片，永久沉淀为知识结构的一部分。

### 1.2 三个关键转变

| 转变 | 从 | 到 |
|---|---|---|
| 内容 → 结构 | 笔记是一整块文本 | 笔记是「知识点的容器」，知识点是一等公民实体 |
| 记录 → 诊断 | 记下你学过的东西 | 推断出你**还没学**的东西（前置知识缺口） |
| 问答 → 沉淀 | AI 回答是流式文字，看完即散 | AI 回答是画布上的卡片，可折叠、可连线、可再追问 |

### 1.3 与现有品类的差别

| 对比 | 差别 |
|---|---|
| Notion | Notion 的结构是用户手搭的、平的；AIMindTree 的结构由 AI 从内容里长出来，组织维度是「知识依赖」 |
| Obsidian | Obsidian 图谱是「发生过什么」的回放；AIMindTree 是「你该学什么」的处方，带掌握状态 |
| 思维导图 | 思维导图整理你**已知道**的；AIMindTree 主打发现你**不知道**的 |
| 通用 AI 问答 | 通用问答无锚点、无记忆、无产出物；AIMindTree 的 AI 有锚点、有掌握状态、有产出物、有教学策略 |
| Anki | Anki 假设你已有卡片；AIMindTree 解决「卡片从哪来」和「先后顺序」 |

### 1.4 目标用户

| 画像 | 特征 | 核心痛点 |
|---|---|---|
| **A（核心）理工科备考学生** | 知识链条长，笔记以公式/定理/推导为主 | 笔记≠知识结构；卡住时不知卡在哪一环；问完就散 |
| B 跨专业自学者 | 无课程大纲兜底 | 学习顺序全靠猜；没有老师可问 |
| C 人文社科考研党 | 需记忆大量概念/人物/流派 | 关系靠死记，缺乏结构化 |
| D（远期 P2）高校助教/讲师 | 学情诊断、备课 | P0/P1 不作为目标用户 |

### 1.5 核心概念（用户视角）

| 概念 | 用户视角的"它是什么" |
|---|---|
| 笔记 Note | 我写的原文，是知识点的来源 |
| 知识点 KnowledgePoint | 一个可以单独操作的东西：标"我会了/不会"、查它依赖谁、拿它问老师 |
| 前置依赖 PrerequisiteEdge | 「要搞懂 A，你得先会 B」，AI 推断或手动连 |
| 知识缺口 KnowledgeGap | 「你还差 3 个知识点才能学懂这个」 |
| 卡片 Card | 一次 AI 回答凝固成的便签，永久留在画布上 |
| 画布节点 CanvasNode | 画布上的一个方块，显示什么取决于它包的是笔记/知识点/卡片 |
| 画布连线 | 实线=知识关系，虚线=归属关系 |
| 掌握状态 Mastery | 未标注 / 未掌握 / 学习中 / 已掌握 / 已放弃 |

## 4. M1 笔记与编辑器

### 4.1 笔记生命周期

| 环节 | 现状 | 位置 |
|---|---|---|
| 列表 | 按 updatedAt 倒序，过滤 `deletedAt.isNull()`；**无搜索框** | `main.dart:299-312` |
| 新建/打开 | `_openEditor(id?)` → 先写 `_lastBody` 再 `setMarkdown`（顺序反了会误标脏） | `note_editor_page.dart:125-135` |
| 编辑 | 点某行/单元格才进编辑态，失焦即回只读 | `note_editor_controller.dart:449-465` |
| 保存 | **仅手动**（AppBar 保存）；标题留空取正文首行；**无自动保存、无撤销栈** | `note_editor_page.dart:419` |
| 脏标记 | 只比较序列化缓存，移动光标不置脏 | `:117-123` |
| 软删除 | 写 `deletedAt` + version+1 + 同步墓碑；可三选：留树 / 从勾选树摘除 / 彻底删除 | `knowledge_repository.dart:411-525` |
| **恢复** | ❌ **未实现**——无笔记回收站（只有知识点有） | — |

### 4.2 块级编辑器

**11 种块类型**（`block_model.dart:49-61`）：段落 / 标题 H1-6 / 引用（连续 `>` 合并成一块）/ 无序列表 / 有序列表 / 任务项 / 围栏代码 / GFM 表格 / 分割线 / 图片 / Raw 兜底。其中 `Divider/Image/Raw` 的 `textEditable=false`。

**行内标记**（`block_model.dart:82-121`）：位掩码 bold1 / italic2 / code4 / strike8，支持组合（boldItalic=3）。序列化优先级 code > strike > `***`/`**`/`*`；code 不与其他叠加。链接退化为 `TextRun.href`，不建模嵌套。

**L1 红线（最重要的技术约束，产品需理解其意义）**：

> 未编辑块的 `source` 原文**字节直通**，`serialize(parse(md)) == md`。

- 怎么保证：块带 `source`（非空=未编辑）时 `_serializeBlock` 直接吐回原文（`markdown_block_parser.dart:523`）；`NoteDoc.prologue` 承载开头空白 + 每块 `trailingGap` 精确重建间隔。强制手段是**块类刻意不提供 `copyWith`**（`block_model.dart:21-22, 273`），改内容必须重造且不传 source。
- **对用户的意义**：打开笔记不改内容 → 保存后字节完全相同 → **不会误标脏、不产生同步假冲突**。这条红线根治了"打开就变脏"和"同步假冲突"两类体验问题。

**键盘与交互**：
- Enter：走 `onChanged` 检测新增 `\n`（不拦按键）。表格=跳下一格/表尾追加行；代码块=软换行、末空行再回车退出；Shift+Enter=软换行。
- Backspace：**必须**在 body 的 `Focus.onKeyEvent` 拦截（`note_editor_body.dart:95-111`），Notion 式两级降级/合并；表格/图片/分割线不跨块合并。
- 工具栏 19 个按钮（`markdown_toolbar.dart:90-164`）；代码块/表格/图片/分割线不支持行内格式 → 置灰但保留 tooltip。

**编辑态仍显示加粗**：`RichLineController.buildTextSpan` 覆写（`note_editor_controller.dart:183-222`）；组字期回退父类，runs 落后一帧时用真实文本切片 + 尾部钳制防 RangeError。

### 4.3 图片资源 `note_assets`

- `data_base64` 是**唯一权威存储**（SQLite 行内），无磁盘缓存目录，内存 LRU 32MB。
- 单图 **2MB 上限**，超限**拒收且不压缩**（`note_asset_repository.dart:38`）；同笔记 sha1 去重。
- 正文只放 `aimindtree-asset://<id>`，缺失降级为"图片未同步"占位。
- 保存时 `reconcileForNote` 回收孤儿附件。

### 4.4 缺口

| 项 | 状态 |
|---|---|
| 图片 / 分割线的点击浮层（替换/删除/改 alt） | ❌ 未实现 |
| 代码块语言选择器 | ⚠️ 只显示不可选 |
| 表格单元格 Tab | ❌ 未实现 |
| 删除表格行/列 | ⚠️ `block_actions` 已实现，**UI 未接** |
| Ctrl+A | ❌ 未实现 |
| **笔记搜索 / 回收站 / 恢复 / 自动保存 / undo-redo** | ❌ 全部未实现 |
| 跨块选区 | ⚠️ 唯一出口是"复制全文" |

### 4.5 产品需知的约束

1. 编辑粒度 = 块内一行，**无 undo/redo**。
2. 每次变更全篇重算序列化 + 整列重建，长文（≥3000 行）性能未优化。
3. Markdown 兼容子集：**不支持嵌套缩进列表**、行内图片（切成独立块）、HTML/脚注/公式、多层强调嵌套。
4. 富文本只有**粗/斜/行内代码/删除线/链接** 5 种，**无颜色/高亮/字号/行对齐**。
5. 保存即入同步 outbox；EdgeOne 链路单条 850KB，大图会被标记 failed。

## 5. M2 知识点管理

### 5.1 数据（核心：防幻觉锚点）

`knowledge_points` 表（`tables.dart:70-98`）必带**来源锚点四件套**：`sourceNoteId` / `sourceStart` / `sourceEnd` / `sourceQuote`。

### 5.2 业务逻辑规则（PM 重点）

| 规则 | 说明 | 位置 |
|---|---|---|
| **锚点防幻觉铁律** | 无逐字 `source_quote`（`indexOf` 命中）→ 剔除**不入库** | `knowledge_repository.dart:126-183`，判定在 `:1100-1106` |
| 手动知识点豁免 | `origin=user_manual` 或 AI 助手检测建议 → 锚点豁免 | `:809-812`；`agent_page.dart:128-145` |
| 最多一个后继 | 每个知识点出边 ≤ 1，已有后继即拒绝 | `:230-236` |
| 防自连 + 防环 | `_canReach` 检测 | `:228, :237-239` |
| 掌握度级联降级 | 标"未掌握"→ BFS 逐层降一档（`maxDepth=32`，source=`tutorCascade`） | `:383-397, :1145-1167` |
| 软删 + 回收站 | 知识点**有**回收站可恢复 | `:527-584`；`knowledge_recycle_bin_page.dart` |
| 删树/删笔记级联 | 清 canvas_nodes / 边 / 掌握记录 | `:404-460` |

**锚点铁律的执行链（端到端）**：
1. 服务端 prompt 强制：`llm_server/prompts/t1_extract.md:39-41` 要求逐字摘抄、`indexOf` 能命中、宁可摘短也绝不为空。
2. App 侧唯一拦截点（**落库前最后一步**）：`saveExtracted` → `_locateQuote()` 返回 null → 加入 `RejectedPoint('锚点校验失败')` → `continue`，**绝不写库**。
3. 所有 AI 提取路径（T1 全量 / T15 单条）都必须经过 `saveExtracted`，**无旁路**。
4. 用户可见反馈：「✅ 已入库 N 条，幻觉剔除 M 条」（`note_editor_page.dart:456-457`）。

### 5.3 筛选与分组（**功能割裂，需产品拍板**）

知识点管理页的筛选维度：类型 / 来源 / 掌握状态 / **分组**。

> ⚠️ **分组功能处于割裂状态**：`kp_groups` 表保留，画布侧已整体下线（`tree_canvas.dart:1242` 注释「分组功能已整体下线」），但**知识点管理页里分组完整存活**——chips 筛选（含"未分组"）+ 分组管理面板 + 批量归组/移到未分组。AI 侧还留着 6 个分组工具（`agent_tools.dart:1009-1163`）。同一个功能一半在、一半不在。

### 5.4 缺口

- **游离知识点无 UI 入口**：筛选里没有「未加入任何知识树」维度；反向入口只有逐条「加入知识树」，且提示"已经在树里了"无法反查。**无全局"游离知识点"视图**。

## 6. M3 知识树 / 画布

### 6.1 数据模型（4 张表）

| 表 | 作用 | 关键字段 |
|---|---|---|
| `canvases` | 画布 = 知识树（一个笔记本可多张） | notebookId、name、viewport |
| `canvas_nodes` | **视图表**，位置/尺寸/层级，严禁内嵌内容 | target_type(`note/kp/card/group`)、target_id、x/y/w/h/z、collapsed、**pinned** |
| `canvas_edges` | 画布连线 | ⚠️ **业务零引用，死表** |
| `knowledge_points` | 知识点是**全局独立资产**，可被多棵树共享 | 锚点四件套、type、definition、origin、confidence |

> **重要**：画布上渲染的连线实际来自 **`prerequisite_edges`** 表，**不是** `canvas_edges`。后者仅在 .g.dart 与同步层搬运，属**断头表**。

| 适应窗口 / 重置视图 | ✅ |

| 手动连线（点起点→终点，Esc 取消） | ✅ |
| 删边（hover 出叉 / 点选后 Delete） | ✅ |
| **框选模式**（右下角悬浮栏常驻开关） | ✅ |

| 网格线显示 | ✅（默认 **false**） |

**模式互斥**：框选模式 ↔ 作业模式 ↔ 画笔/橡皮三者互斥，共用 `_selectedKpIds`。

### 6.3 自动布局（`layout_engine.dart`）

- **分层规则**：`level = max(前置.level)+1` 的 BFS relaxed 分层；**每层占一行，层内不限个数**；环保护残留置 0。
- **同层排序**：领域（用 `sourceNoteId` 近似，因无领域字段）→ type → 名称。
- **两区布局**：有边点走拓扑分层置顶；**无边点**统一铺到下方，每行 `isolatedPerRow=10`。
- **全量重排 `_onRelayout()`**：跑 `layoutForest` → 所有节点写回 **pinned=true（全锁）**。**不删 canvas_nodes 行**（那行同时是树成员关系）。
- **局部重排**：只算子集，`findFreeBlockTopLeft` 整体避让未选中节点。
- ⚠️ **重排只有两个触发点**：手动「重新布局」和「局部重排」。连边 / 删边 / 自动连线 / 新增知识点**都不重排**（新增点只走避让式落位 `_autoPlaceNewPoints`）。

### 6.4 缺口

| 项 | 状态 |
|---|---|
| `canvas_edges` 表 | ❌ 死表，业务零引用 |
| 节点折叠 `collapsed` | ❌ 未接线 |
| 游离知识点视图 | ❌ 无入口 |
| 分组在画布 vs 管理页 | ⚠️ 割裂，需拍板 |
| 重排无自动触发，且一点就全锁 | ⚠️ 交互待优化 |
| `gridSize` / `showGrid` | ⚠️ 硬编码，**UI 无开关** |

## 7. M4 AI 能力（T1–T15）

### 7.1 任务全景（**15 类，不是 5 类**）

定义：`ai/ai_task.dart:8-23`；服务端映射：`llm_server/prompts/index.yaml:6-23`。

| 任务 | UI 入口 | 输出 / 落库 | 状态 |
|---|---|---|---|

## 10. M7 同步与账号

### 10.1 现状：手动同步

`sync_scheduler.dart:3` 明写「自动调度已下线」；`extraction_service.dart:581-585` 只 new SyncScheduler，**不调 start**。入口只有设置页两个按钮。

- **上传** = `pushDrain`（增量排空）+ `pushAll`（全量快照，16 张表现存行全推），分开计数上报「增量 N + 快照 M」。
- **拉取** = `pull`，**每次强制游标归零 → 实际是全量拉**。

### 10.2 冲突与版本（业务逻辑）

- **LWW**（`sync_engine.dart:687-725`）：remote.deletedAt≠null 硬删本地 → baseVersion 大者赢 → 相等比 updatedAt → 自回声（deviceId 相同）跳过。
- **版本机制（服务端权威）**：push 时中继算 `newVer = max(服务器, 客户端 baseVersion) + 1` 并回 `versions`；App 侧 `_adoptServerVersions` 每批成功后**只写 version 一列**。**pull 侧不调版本**——直接把 `baseVersion` 落地成本地 version。
  - 用户可感知：① 从没上传过的设备拉下来的行版本由服务端塞；② 跨设备「最后一次上传者赢」；③ **"数据版本"卡里本机/服务器数字不必然相等**（这是设计使然，不是 bug）。
- **无冲突提示、无冲突解决 UI，pull 直接覆盖。**

### 10.3 三条中继链路

| 后端 | 定位 | 推送预算 / 单条硬限 | 特点 |
|---|---|---|---|
| Cloudflare Worker | 海外/备用 | 4MB / 6MB | 地址内置已部署；DoH 直连探测 |
| **EdgeOne Pages** | **国内主力** | **850KB / 850KB** | 永久免费、1GB KV、国内可达好；请求体 1MB 硬限；KV 键名只许 `[A-Za-z0-9_]`；KV 最终一致 ~60s → pull 自带 65s lookback |
| Netlify | 海外/备份 | 4MB / 6MB | 函数跑美/欧单区，国内可达性差 |

- 超单条硬限 → `markFailed` + warning，不堵队列；收到 413 会给中文提示「压缩图片或更换后端」。
- **大图片**：单张上限 2MB，base64 再涨 33% → EO 850KB 必然拒收，只能切 CF/Netlify。

### 10.4 逃生舱

设置页「服务器与网络」：自定义同步地址（按后端）+ HTTP 代理 + 保存 + 测试连接。测试连接判据是 **200，或 401 且 body 里 `error=="unauthorized"`**（避免把平台 404 误判为连通）。保存后提示「需重启应用后完全生效」。

### 10.5 缺口

| 项 | 状态 |
|---|---|
| **EdgeOne 未上线** | ❌ `kSyncEoDefaultBaseUrl = ''` → UI 显示「（待配置）」，上传/拉取按钮**禁用**。控制台 KV 命名空间 Variable Name 必须绑 `SYNC_KV` |
| 未登录/未配地址时 | ⚠️ api 退化为 `MockSyncApi` 占位，用户不主动进设置页则**全程无同步** |
| 自动/后台/定时同步 | ❌ 无 |
| 增量拉取 | ❌ 拉取恒为全量，数据量大时慢 |
| 冲突解决 UI | ❌ 无 |
| 大图片自动压缩/换链路 | ❌ 只提示用户手动切 |
| `homeworks` 跨设备 | ✅ 已纳入同步（16 张同步表之一） |
| `retryFailed` 指数退避 | ⚠️ 声称有，**实际无退避**（每轮无差别重试） |
| 密钥加密 | ⚠️ SecretStore 是**明文 JSON 文件**，未上 flutter_secure_storage |

## 15. 给产品同学的三句话

1. **核心闭环是通的**：写笔记 → 抽知识点（带锚点防幻觉）→ 补前置 → 老师教 → 沉淀卡片 → 标记掌握，这条主链路功能完整且有独特的产品价值（诊断"你缺什么"而非记录"你有什么"）。
2. **最大的体验风险是"割裂"**：分组一半在、AI 连线永远失败、笔记没有回收站但知识点有、国内同步链路按钮是灰的——用户会遇到"这个功能明明有，为什么用不了"。
3. **最值得优先讨论的三个方向**：① 补齐笔记侧的基础体验（搜索/回收站/自动保存）；② 拍板分组与 T3/T4 的去留并给出可达的配置入口；③ 打通 EdgeOne 让国内同步真正可用。
