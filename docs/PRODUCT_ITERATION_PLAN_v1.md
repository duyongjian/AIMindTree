## 0. 三十秒速览（结论先行）

- **现状**：核心闭环（写笔记 → 抽知识点（锚点防幻觉）→ 补前置 → 老师教 → 沉淀卡片 → 标记掌握）**功能完整且有真差异化**（诊断"你缺什么"，而非记录"你有什么"）。
- **核心病根不是"功能少"，是"割裂"**：同一个能力一半在、一半不在；点了必然失败的入口没清理；笔记没有回收站但知识点有；国内同步按钮是灰的。用户反复遇到"这功能明明有，为什么用不了"。
- **本版迭代主题**：**「要么完整可用、要么明确下线」**——消除割裂，而非继续堆功能。
- **三个工作包**：A 补齐笔记侧基础体验（搜索/回收站/自动保存）；B 拍板并执行割裂项（T3/T4、分组、游离知识点、collapsed、canvas_edges）；C 打通 EdgeOne 让国内同步真正可用。另并入性能优化第一批。

## 1. 迭代目标与成功标准

### 1.1 本版目标（一句话）

> 把"功能都有但用不了"的割裂态，收敛成"每个入口要么跑得通、要么干干净净地消失"，同时补齐笔记侧天天被踩的基础体验硬伤。

### 1.2 成功标准（可验收）

| 编号 | 目标 | 判定方式 |
|---|---|---|
| G-1 | **割裂项清零**：文档 §13-B 的 4 项割裂（分组 / T3+T4 / 笔记回收站 / 同步按钮）全部有明确处置并落地 | 逐项验收，无"半在半不在"残留 |
| G-2 | **无"必失败入口"**：用户点得到的功能，100% 要么成功、要么给出可执行引导（如"去哪里配置"） | 全量入口走查，零"点了只报失败" |
| G-3 | **笔记侧三件套上线**：搜索 / 回收站+恢复 / 自动保存 | 功能验收（见 §7） |
| G-4 | **国内同步可用**：EdgeOne 链路可上传可拉取 | 真机实测一次完整上传+拉取 |
| G-5 | **性能达标**：沿用 10-24 已定标准（画布 L1/L2 帧率、切 Tab 往返 ≤3 次等） | 见 `performance_goals_and_criteria_2026-10-24.md` |
| G-6 | **核心能力不回退**：锚点防幻觉铁律、级联降级、LWW/幂等、L1 字节直通红线 | 回归测试全绿 |

> **关于数据指标**：主理人已决策埋点暂缓（自用阶段），故本版**以"功能可用性"为验收基准，不设数据类 KPI**。若后续需验证用户价值，最小埋点应单独立项（已记入后续版本池）。

## 4. 关键决策点的方案对比（需拍板）

### D-1 ｜ T3 / T4 去留（主理人已定 T3 取消，此处收敛执行方式）

| 方案 | 做法 | 成本 | 体验 | 风险 | 评价 |
|---|---|---|---|---|---|
| **A（推荐）** | T3 正式下线（清入口+清 `autoLinkByGroups`）；**T4 保留并修复可达**（未绑定 dedicated 路由时回落默认 provider 并 toast 提示"使用默认模型"，而非直接失败） | 低-中 | 好：保住"诊断你缺什么"的核心价值，且是"AI 建议 + 人勾选"的可控形态 | 低 | **推荐**。T4 是产品定位的承载者，不该废 |
| B | T3/T4 双双下线 | 低 | 差：核心差异化"补前置/缺口诊断"消失 | 中（自废武功） | 备选 |
| C | 都保留，仅靠后台配 `ai_task_routes` | 低 | 差：用户仍会遇到"点了必失败"，割裂未消除 | 中 | 不推荐 |

**推荐 A**。理由：主理人取消 T3 的实质是拒绝"AI 自作主张改结构"；T4 恰是"AI 建议 + 人工拍板 + 锚点兜底"的可控形态，与产品定位一致，应保留并修好。

### D-2 ｜ 分组去留（当前割裂：画布下线 / 管理页存活 / AI 侧 6 工具）

| 方案 | 做法 | 成本 | 体验 | 风险 | 评价 |
|---|---|---|---|---|---|
| **A（推荐）** | **收敛下线**：管理页分组入口隐藏、`kp_groups` 表保留（可恢复）、AI 侧 6 工具隐藏。若仍需"分类筛选"，后续以**标签**概念复用同批数据 | 中 | 好：组织维度统一到"知识树"，消除割裂 | 中（需确认管理页分组无强依赖用户） | **推荐** |
| B | **恢复画布侧分组**，与管理页对齐 | 高 | 中：功能全了，但引入"知识树 vs 分组"两个平行组织维度，心智负担重 | 中 | 备选 |
| C | 维持现状 | 0 | 差：割裂持续，用户困惑 | 低 | 不推荐 |

**推荐 A**，但**需主理人拍板**（取决于你自用时是否真的在用管理页的分组筛选）。

### D-3 ｜ 笔记回收站形态

| 方案 | 做法 | 成本 | 体验 | 评价 |
|---|---|---|---|---|
| **A（推荐）** | **复用知识点回收站交互**（`knowledge_recycle_bin_page.dart` 模式）：软删入站 → 列表可恢复/彻底删除 → 支持清空 | 中 | 好：**与知识点回收站一致**，正是"消除割裂" | **推荐** |
| B | 轻量：仅"最近删除"列表 + 单条恢复 | 低 | 中：能防误删，但与知识点回收站体验不一致 | 备选 |

**推荐 A**：本版主题就是消除割裂，回收站形态自相矛盾没有道理。

### D-4 ｜ 老师模式状态机（`tutor_state` 恒 `{}`、`difficulty` 从未写入）

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（推荐）** | **落地最小状态机**：`difficulty` 真实落库（三档）、`tutor_state` 记录当前阶段（讲解/提问/纠正），使"再讲一次/追问"有策略差异 | **推荐**。老师模式是核心闭环一环，空实现 = 隐性割裂 |
| B | 正式下线两列 | 备选（若判断教学策略非本阶段重点） |
| C | 维持空实现 | 不推荐（死字段误导维护） |

## 5. 优先级排序（MoSCoW 收口）

由于埋点暂缓、无真实 Reach/Impact 数据，本版**用 MoSCoW 收口而非 RICE 评分**（RICE 需实测触达数据，强行打分会失真）。排序逻辑：**割裂清零 > 天天被踩的基础体验 > 差异化能力修复 > 体验增强**。

| 桶 | 需求 | 理由 |
|---|---|---|
| **Must** | R-01 自动保存、R-02 笔记回收站、R-03 搜索、R-04 T3 下线、R-05 T4 修复、R-06 分组拍板、R-07 EdgeOne、R-08 性能第一批 | 直接对应 G-1~G-5；前三项是天天被踩的硬伤，后四项是割裂清零 |
| **Should** | R-09 老师模式状态机、R-10 游离知识点视图、R-11 同步体验、R-12 编辑器接线、R-13 死代码清理 | 补核心闭环缺口 + 低成本接线 |
| **Could** | R-14 增量拉取、R-15 undo-redo、R-16 网格开关、R-17 图片浮层、R-18 未接线任务评估 | 体验增强，排期允许再做 |
| **Won't** | 密钥加密、配置热更新、冲突解决 UI 完整版、homeworks 同步、大图压缩、移动端首发、埋点 | 本期不做，记后续版本池 |

## 7. 关键需求的验收标准（GWT，可直接转测试用例）

| 编号 | 验收标准 |
|---|---|
| R-01 | Given 编辑笔记，When 停止输入 2s（或失焦），Then 自动入 `sync_outbox` 且列表 updatedAt 更新；给定手动保存仍可用，二者不冲突 |
| R-02 | Given 删除笔记，When 进入回收站，Then 可见该笔记并可恢复；恢复后笔记内容与删除前一致、知识点关联不丢；彻底删除后不可恢复 |
| R-03 | Given 笔记 ≥50 篇，When 输入关键词，Then 300ms 内返回标题/正文命中结果；无结果有空态引导 |
| R-04 | Given T3 已下线，When 打开画布工具栏，Then 无"自动连线/局部连线"入口；点击任何 AI 入口均不出现"自动连线失败" |
| R-05 | Given T4 未配 dedicated 路由，When 点"补充前置知识"，Then 回落默认 provider 正常返回建议列表（toast 提示使用默认模型），而非直接失败 |
| R-06 | Given 分组拍板结论，When 走查三个入口（画布/管理页/AI 工具），Then 三者状态一致（全有或全无），无"一半在" |
| R-07 | Given EdgeOne 已绑 KV，When 点上传/拉取，Then 按钮可用且完整跑通一次；失败有中文原因 |
| R-08 | 见 `performance_goals_and_criteria_2026-10-24.md` C-01~C-08 |
| R-10 | Given 存在未入任何树的知识点，When 打开游离知识点视图，Then 全部可见并可批量入树/删除 |
| G-6 | 锚点铁律、级联降级、LWW/幂等、L1 字节直通（`serialize(parse(md))==md`）回归测试全绿 |
