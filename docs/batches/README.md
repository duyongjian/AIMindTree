**依赖关系（先做前一批再做后一批的项）**

```
BATCH-1 ──┐
          ├──► BATCH-4 ──► BATCH-5
BATCH-2 ──┘        ▲
                   │（R-10 需先有 R-06 分组口径结论）
BATCH-3（R-07 阻塞：EdgeOne 控制台绑 KV，非代码可控）
```

- **BATCH-3 / R-07 是唯一有外部阻塞项的需求**：KV 未绑定则代码改完也不可用，须先排运维。
- **BATCH-2 / R-06 需主理人拍板后才派工**（收敛下线 vs 恢复画布侧）。

## 3. 跨批通用红线（每一批都必须遵守）

> 以下为项目既有铁律，违反会导致回归事故。派工时请随卡片一起交给技术。

| # | 红线 | 说明 |
|---|---|---|
| 1 | **L1 字节直通** | 未编辑块的 `source` 原文字节直通，`serialize(parse(md)) == md`。任何改动不得破坏，改动笔记写入路径必须加回归断言 |
| 2 | **锚点防幻觉铁律** | 无逐字 `source_quote`（`indexOf` 命中）的知识点**禁止入库**。所有 AI 提取路径必须经 `saveExtracted`，无旁路 |
| 3 | **不改 Drift 表后忘跑 build_runner** | `dart.exe run build_runner build`（约 14s），禁手工改 `.g.dart` |
| 4 | **同步布尔容错** | 读侧禁 `as bool?`，一律 `_bool(v, fallback)`；fallback 抄 `tables.dart` 的 `withDefault`（`knowledge_points.pinned=false`、`canvas_nodes.pinned=**true**`、`canvas_nodes.collapsed=false`） |
| 5 | **同步契约** | 新增列必须上行同步；查列集必须真查库 `PRAGMA table_info(<表>)`，不能靠源码扫描 |
| 6 | **新增写库点必须触发刷新** | 项目用构造函数注入 + setState + 刷新总线，新增写库点忘触发刷新 = "数据改了 UI 不刷" |
| 7 | **不改 `canvas_nodes` 行语义** | 该行同时是"树成员关系"，删除 = 退出树，不要当成纯视图记录删 |
| 8 | **禁裸 catch** | 用 `result.dart` 的 Success/Failure |

### 门禁（每批交付前必跑）

```bash
# 1) 静态门禁：错+警都必须为 0
cd aimindtree_app && dart.exe tool/analyze_inproc.dart

# 2) 测试：必须串行（并发抢 sqlite3.dll 会静默退场，看起来像全绿）
HTTP_PROXY= HTTPS_PROXY= http_proxy= https_proxy= ALL_PROXY= all_proxy= flutter test
# 跑前确认无残留进程：tasklist | grep -ci "dart.exe\|flutter_tester" 必须为 0

# 3) 提交前：工作区不得有未跟踪文件
git status --porcelain   # 不得出现 ??
```

### 每批的完成定义（DoD）

1. 该批全部需求的 GWT 验收标准逐条通过；
2. `analyze_inproc.dart` 0 错 0 警；
3. `flutter test` 全绿且用例数**不减少**（当前基线 884/884，以实际为准）；
4. 跨批红线 8 条无违反；
5. 若有性能项，需留下 before/after 度量记录（截图/往返计数/耗时日志），否则不算完成。

## 4. 派工建议（给主理人）

- **第一次派工**：`BATCH-1` + `BATCH-2` 一起给技术（文件域不重叠，可并行），但 **R-06 需你先拍板**再放进 BATCH-2。
- **R-07 单独处理**：先去 EdgeOne 控制台绑 KV（`SYNC_KV`，大小写敏感），拿到域名后再派代码活。
- **BATCH-3 的 R-08 性能**：派工前先测一批基线（切 Tab 数据库往返次数、画布 50 节点帧率），没有 before 就无法证明 after。
- **不要一次派 5 批**：批次之间验收口径会互相影响，一批验完再派下一批。
