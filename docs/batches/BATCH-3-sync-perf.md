## R-07 ｜ 打通 EdgeOne（国内同步真正可用）

### 一句话

把国内主力同步链路接上，让设置页那个灰掉的"上传/拉取"按钮能点、能跑通。

### 为什么要做

EdgeOne 是国内主力链路（永久免费、1GB KV、国内可达好）。现在 `kSyncEoDefaultBaseUrl = ''` 导致 UI 显示「（待配置）」、**上传/拉取按钮禁用**。而 CF 受 DNS 投毒 + TLS SNI 级 RST 阻断、Netlify 国内可达性差——**等于国内实际上没有可用的同步**。

### 现状证据

| 事实 | 位置 |
|---|---|
| `kSyncEoDefaultBaseUrl = ''`（空串） | `lib/data/sync/sync_config.dart:103` |
| 空串 → UI 显示「（待配置）」 | 同上；§10.5 |
| 后端选择为 edgeone 时按钮禁用 | `lib/features/settings/sync_settings_section.dart:566` |
| KV 命名空间 Variable Name **必须**绑 `SYNC_KV`（大小写敏感） | §10.3、工作记忆 #51 |
| 推送预算 **850KB**（超限 markFailed）；请求体 1MB 硬限 | §10.3 |
| KV 最终一致 ~60s → pull 自带 65s lookback | §10.3 |
| 单图 2MB + base64 涨 33% → EO 850KB 必然拒收（已知，本期不解决） | §10.3 |

### 怎么做

**第一步（运维，非代码，必须先做）**
1. EdgeOne 控制台 → 绑定 KV 命名空间，**Variable Name 严格为 `SYNC_KV`**（大小写敏感，写错就是 503）。
2. 绑定自定义域名（默认域名会 401）。
3. 拿到可用域名后回填 `sync_config.dart:103` 的 `kSyncEoDefaultBaseUrl`。

**第二步（代码）**
4. 回填地址后，`sync_settings_section.dart:566` 的判空自动失效，按钮恢复可用——**确认无需另改逻辑**。
5. 真机验证：完整跑一次 **上传**（`pushDrain` 增量 + `pushAll` 全量）与一次**拉取**，观察计数上报「增量 N + 快照 M」。
6. 失败提示中文原因确认：已有 413 →「压缩图片或更换后端」；补充对 401/503 的中文解释（401=域名未绑自定义域；503=KV 未绑定）。
7. 大图片（>850KB）会被 markFailed：本期**只保证提示清晰**，不解决压缩/自动换链路（已记 Won't）。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | EdgeOne 已绑 KV 与域名 | 设置页选择 EdgeOne | 上传/拉取按钮**可用** |
| 2 | 点上传 | 完成 | 计数上报「增量 N + 快照 M」；非大图情形下 **failed = 0** |
| 3 | 另一设备拉取 | 完成 | 数据一致，无异常 |
| 4 | 大图（>850KB） | 上传 | 明确标记 failed 并给出中文原因，**不堵队列** |
| 5 | KV 未绑（503）/ 域名未绑（401） | 操作 | 给出对应中文原因，不是笼统"失败" |

## R-08 ｜ 性能第一批（掌握度批量查询 / 批量操作打包 / 重绘隔离）

### 一句话

把切 Tab 时的"逐条查库"改成"一次查完"，把节点卡片加上重绘隔离，让画布拖动更省。

### 为什么要做

切一次画布 Tab，现在会对**每个知识点各查一次数据库并各刷一次界面**（N+1），节点越多越慢；画布上每个节点也没有重绘隔离，拖动/缩放时会连带着重绘没变化的卡片。PRD 验收要求 300 节点 ≥50fps，按当前实现规模一上来就吃紧。

### 现状证据

| 事实 | 位置 |
|---|---|
| 载入画布时**循环内**逐个 `await _repo.currentMastery(p.id)`，且**每个点一次 `setState`** | `canvas_page.dart:219-223` |
| `_mastery` 是全量 map，逐点填充 | `canvas_page.dart:213-222`；`_masteryOf` `:235` |
| 节点卡片渲染处 | `canvas/render/tree_canvas.dart:1371`（传 `widget.currentMastery(n.kpId)`） |
| 全仓 **0 处 `RepaintBoundary`**（grep 无命中） | 全仓搜索结果 |
| 性能目标与验收口径（C-01~C-08） | `.workbuddy/performance_goals_and_criteria_2026-10-24.md` |

### 怎么做

1. **掌握度批量化（首要）**
   - 新增 `currentMasteryBatch(List<String> ids)`（repository 层），一次查询返回 `Map<String, MasteryStatus>`。
   - `canvas_page.dart:219-223` 的循环改为：一次 await → 一次 `setState` 整体赋值。
   - 语义必须**逐条等价**：缺失 id 回落 `MasteryStatus.unknown`（与现状一致）。
2. **批量操作走事务打包**
   - 审查批量删除 / 批量移动 / 批量入树：若现状是循环内逐条写库，改为单事务（`transaction(() async {...})`）批量提交。
   - 目标：批量删 50 点数据库往返 ≤5 次、≤1 秒。
3. **重绘隔离**
   - 每个节点卡片包一层 `RepaintBoundary`（`tree_canvas.dart` 节点渲染处，约 `:1371` 附近）。
   - 这是成本极低、收益明显的一项：平移/缩放时只重绘变化的卡片。
4. **先测基线再改**（必做）：改前记录——切 Tab 数据库往返次数、画布 50 节点帧率。没有 before 无法证明 after。

### 验收标准（GWT）

> 具体数值口径见 `performance_goals_and_criteria_2026-10-24.md`（C-01~C-08），此处列直接相关项。

| # | Given | When | Then |
|---|---|---|---|
| 1 | 画布含 50 个知识点 | 切到知识树 Tab | 数据库往返 **≤3 次**（原为 N+1 次）；`setState` **1 次** |
| 2 | 画布含 50 个知识点 | 拖动/缩放 | L1 规模帧率达标（见目标文档：日常规模 ≥60fps） |
| 3 | 选中 50 个点批量删除 | 执行 | 数据库往返 **≤5 次**、耗时 **≤1 秒** |
| 4 | 画布含 300 个知识点（L3） | 拖动/缩放 | 帧率 **≥50fps**（PRD 验收线） |
| 5 | 任意规模改动前后 | 比对 | 掌握度显示**逐条一致**（用快照比对，见风险 RK-08） |
| 6 | 全仓检查 | grep | **0 处新增 N+1**（循环内 await 查库） |

### 风险与红线

- **RK-08（中）**：性能优化改动批量查询语义，可能导致掌握度显示偏差。应对：**改前导出 mastery 快照，改后逐条比对**，差异必须为 0。
- 红线 #6（新增写库点必须触发刷新）：批量化后刷新时机变化，务必确认界面仍刷新。
- 红线 #4（同步布尔容错）：若批量查询涉及 `canvas_nodes` 的 `pinned/collapsed`，fallback 必须抄 `tables.dart` 的 `withDefault`（`pinned` 默认 **true**）。

### 估算

**1–2 人天（估算）**，含基线测量 0.5 天。

## R-11 ｜ 同步体验（冲突提示 + 进度反馈粒度）

### 一句话

拉取覆盖了本地更新要告诉用户；长任务排队要显示"在干什么、等了多久、能取消"。

### 为什么要做

现在 **pull 直接覆盖，无冲突提示**（§10.2），用户会莫名其妙发现本地改动没了；而本机 27B 约 8 tok/s + 队列并发 1，长任务是分钟级排队，**UI 只有顶部一条细进度条**（§13-C），用户会以为卡死。

### 现状证据

| 事实 | 位置 |
|---|---|
| **无冲突提示、无冲突解决 UI，pull 直接覆盖** | §10.2 |
| 进度反馈粒度粗：长任务分钟级排队，UI 只有顶部细条 | §13-C |
| `retryFailed` 声称有指数退避，**实际无退避**（每轮无差别重试） | §10.5 |
| LWW 规则：remote.deletedAt≠null 硬删本地 → baseVersion 大者赢 → 相等比 updatedAt → 自回声跳过 | `sync_engine.dart:687-725` |
| "数据版本"卡：本机/服务器数字不必然相等（设计使然） | §10.2 |

### 怎么做

1. **冲突提示（最小版）**：拉取完成后，若本次 pull 覆盖了本地更新的行，给出提示「本次拉取覆盖了 N 条本地更新」（含数量）。**本期不做冲突解决 UI**（已记 Won't），但必须让用户知道发生了覆盖。
2. **进度反馈粒度**：长任务（AI 队列 / 同步）显示：当前任务名 + 已等待时长 + **取消**按钮。避免用户怀疑卡死。
3. **`retryFailed` 退避**：补上真正的指数退避（如 1s/2s/4s…上限，具体参数为估算值需实测），替代当前无差别重试。
4. 注意：不要动 LWW 语义本身（改冲突**判定**风险高，本期只做告知）。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | 本地有更新且服务器版本更新 | 执行拉取 | 完成后明确提示「本次拉取覆盖了 N 条本地更新」，N 准确 |
| 2 | 无覆盖发生 | 执行拉取 | **不弹**覆盖提示（避免狼来了） |
| 3 | 提交一个长任务 | 等待 >10s | UI 显示当前任务名 + 已等待时长 + 可取消 |
| 4 | 失败项重试 | 连续失败 | 退避间隔递增（可日志验证），不是每轮无差别重试 |

### 风险与红线

- 改动 LWW 判定本身风险高——**本期只做提示，不改判定**（验收里不含任何覆盖规则的变更）。
- 红线 #8（禁裸 catch）。

**1 人天（估算）**
