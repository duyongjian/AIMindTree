## R-04 ｜ T3（自动连线）正式下线

### 一句话

把画布上"自动连线/局部连线"这两个点了**必然失败**的入口彻底删掉，不留半死不活。

### 为什么要做

主理人已决策**取消 T3（AI 自动补前置）**，理由是"太不可控"。但代码里入口还在，而 T3 依赖的 `ai_task_routes` 表默认为空、App 无维护入口、路由未命中即 `return null` 禁止回落 → **事实 100% 失败**。用户点下去只会看到「自动连线失败：…」，且**没有"去哪里配置"的引导**。这是标准的"必失败入口"，符合本版"要么可用要么消失"的处置原则。

### 现状证据

| 事实 | 位置 |
|---|---|
| T3 入口：画布「自动连线」 | `canvas_page.dart:1514` `_autoLink`；同步路径 `:1561` |
| T3 入口：「局部连线」（需框选 ≥2 点） | `canvas_page.dart:1605` `_autoLinkSelected`；同步路径 `:1665` |
| 复合链「提取 → 入树 → 自动连线」也调用 | `canvas_page.dart:2613`、`:2858` |
| 工具栏按钮组说明（连线系列） | `canvas_page.dart:3098-3099` |
| `autoLinkByGroups`：**代码有、UI 未接** | §13-A；`auto_graph_service.dart` |
| 路由开关：`_dedicated = {T3, T4}`，未命中 → `return null`，**禁止回落** | `ai_task_router.dart:34-37` |
| provider 为 null → Failure「AI 服务未连接…」 | `ai_service.dart:44-52` |

### 怎么做

1. **先全仓引用核查**（必做）：`grep -rn "_autoLink\|autoLinkSelected\|autoLinkByGroups\|\.autoLink("`，列出全部调用点，尤其确认 **Agent 的 32 个工具**里是否有连线相关工具（若有，一并处置或标注废弃）。
2. 删除画布工具栏「自动连线」「局部连线」入口，及对应实现 `_autoLink` / `_autoLinkSync` / `_autoLinkSelected` / `_autoLinkSelectedSync`。
3. 删除 `autoLinkByGroups` 死代码。
4. 改复合链（`canvas_page.dart:2613`、`:2858`）：**去掉自动连线步骤**，改为"入树 → 自动落位 → 完成"，不报错、不提示连线未完成。
5. `_dedicated` 集合里移除 T3（`ai_task_router.dart:34-37`）；若确认已无任何调用方，`auto_graph_service.autoLink` 一并删除（若 Agent 工具仍引用，保留函数但标注 `@Deprecated` 且不暴露 UI）。
6. 同步更新相关文案：画布空态文案（§6.4 提到空态文案仍写「该笔记还没有提取出知识点」，已过期，可顺手改）、帮助提示、框选模式 toast（`:2118` 提到"局部重排 / 局部连线"）。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | 打开画布工具栏 | 查看 | **无**「自动连线」「局部连线」入口 |
| 2 | 点击任何 AI 入口 | 操作 | 不出现「自动连线失败」类提示 |
| 3 | 执行「提取 → 入树」复合链 | 完成 | 知识点正常入树落位，**不触发连线且不报错** |
| 4 | 开框选模式 | 看提示文案 | 不再出现"局部连线"字样 |
| 5 | 全仓 grep | 搜索 `autoLink` | 无残留 UI 引用（保留的废弃函数须有 `@Deprecated` 标注） |
| 6 | 编译 + 测试 | 门禁 | 0 错 0 警，测试全绿 |

### 风险与红线

- **RK-06（低→中）**：删除误伤仍被引用处。应对：第 1 步引用核查 + 编译期保证 + 测试全绿。
- 红线 #8（禁裸 catch）；删除后若留废弃函数必须显式标注，避免再变成新的"死代码"。

### 估算

**0.5–1 人天（估算）**

## R-05 ｜ T4（补前置建议）修复可达

### 一句话

让"补充前置知识"真正能用——没配专用模型时**回落到默认模型并提示**，而不是直接失败。

### 为什么要做

T4 是**产品定位的承载者**：它输出的是"你可能缺哪些前置知识"的**建议列表**，默认全选、**由用户勾选后才入库**，且入库要过锚点校验——这正是"AI 建议 + 人工拍板 + 锚点兜底"的可控形态，与主理人取消 T3（AI 自作主张改结构）的理念**完全一致**。

但现在 T4 因为和 T3 共用 `_dedicated = {T3, T4}` 开关，被 T3 一起拖死：路由未命中 → `return null` → Failure。**不修等于自废"诊断你缺什么"这个最值钱的差异化。**

### 现状证据

| 事实 | 位置 |
|---|---|
| T4 入口：节点浮层「补充前置知识」→ 深度 low/medium/high/custom | `canvas_page.dart:1744`、`:1816` |
| T4 入口：工具栏「批量补前置」 | `canvas_page.dart:2007`、`:3217` |
| T4 输出**不入库**，仅建议列表弹窗 | §7.1 表格 |
| 建议模型 `SuggestedPrerequisite` | `lib/data/models/suggested_prerequisite.dart` |
| 路由未命中 → `return null` 禁止回落 T1 | `ai_task_router.dart:34-37` |
| provider 为 null → Failure「AI 服务未连接…」 | `ai_service.dart:44-52` |
| 解析/调用失败一律 Failure，**无本地兜底** | §7.3 |

### 怎么做（方案 A，推荐）

1. 在路由层对 **T4 单独允许回落默认 provider**：`ai_task_routes` 未命中 dedicated 路由时，T4 使用默认 provider 执行（**仅 T4，不改 T1/T5/T14，不恢复 T3**）。
2. 回落时给用户**明确提示**：toast「未配置专用模型，正在使用默认模型」——不能悄悄换模型。
3. 保留 dedicated 能力：后台一旦配了 T4 路由，仍优先用配置的（行为不变）。
4. **改写失败文案**：把"AI 服务未连接"改成**可执行引导**——「AI 服务未连接：请先启动本机 llm_server，或在设置页查看服务状态」。原来的文案用户看完不知道下一步干嘛。
5. 不改 T4 的输出语义：**建议不入库**、入库仍须过锚点校验（红线 #2 不可破）。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | 未配 T4 dedicated 路由 | 点「补充前置知识」 | 正常返回建议列表（**不是失败**），顶部/toast 提示「使用默认模型」 |
| 2 | 本机 llm_server **未启动** | 点击 | 提示「AI 服务未连接：请先启动本机 llm_server，或在设置页查看服务状态」 |
| 3 | 已配 T4 dedicated 路由 | 点击 | 走配置模型，行为与现状一致 |
| 4 | 建议列表勾选后入库 | 走 T1 锚定路径 | 无逐字 `source_quote` 的条目**仍被剔除**，不入库（锚点铁律不破） |

### 风险与红线

- **RK-03（中）**：回落可能用错模型——原设计**刻意**禁止回落 T1 是有原因的。
  - 应对：回落**仅对 T4 生效**（不改 T3、不改其他任务）；toast 明示"使用默认模型"；保留后台可配 dedicated。
- 红线 #2（锚点铁律，验收 #4 覆盖）。

### 估算

**0.5 人天（估算）**

## R-06 ｜ 分组去留拍板并执行 ⚠️ 需主理人先拍板

### 一句话

分组现在"画布没有、知识点页面有、AI 助手里还有 6 个工具"——三处不一致，必须统一成"全有"或"全无"。

### 为什么要做

§13-B 把它列为**头号功能割裂**，§5.3 明确标注"需产品拍板"。用户会遇到"这功能明明有，为什么这里用不了"。

### 现状证据

| 事实 | 位置 |
|---|---|
| 画布侧：**已整体下线**（注释「分组功能已整体下线」） | `canvas/render/tree_canvas.dart:1242` |
| 知识点管理页：**完整存活**——chips 筛选（含"未分组"）+ 分组管理面板 + 批量归组/移到未分组 | `knowledge_manage_page.dart:64-72`（筛选 `:104-106`）、`:465-507`（设置分组）、`kp_group_manage_sheet.dart`、`group_repository.dart` |
| AI 侧仍留 **6 个分组工具** | `agent_tools.dart:1009-1163` |
| `kp_groups` 表保留且参与同步 | §12 表 #13 |
| 页面注释自己写着"**分组只在知识点界面出现**，不进知识树" | `knowledge_manage_page.dart:11` |

### 方案对比

| 方案 | 做法 | 成本 | 体验 | 评价 |
|---|---|---|---|---|
| **A（推荐）收敛下线** | 管理页隐藏分组 chips / 「设置分组」菜单 / 「分组管理」入口；隐藏 Agent 6 个分组工具；**`kp_groups` 表与同步保留**（可恢复） | 中 | 好：组织维度统一到"知识树"，割裂消除 | **推荐** |
| B 恢复画布侧 | 画布重新支持分组，与管理页对齐 | 高 | 中：功能全了，但引入"知识树 vs 分组"两个平行组织维度，心智负担重 | 备选 |
| C 维持现状 | 0 | — | 差：割裂持续 | 不推荐 |

> 未来若确实需要"分类筛选"，建议以**标签**概念复用同批数据，而不是把分组搬回画布。

### 怎么做（方案 A）

1. 知识点管理页：隐藏分组 chips 行（`:64-72`、`:104-106`）、条目菜单里的「设置分组」（`:465-507`）、「分组管理」入口。
2. Agent 工具：隐藏 6 个分组工具（`agent_tools.dart:1009-1163`），从工具列表中移除注册。
3. **保留** `kp_groups` 表、repository、同步行映射（可恢复，不动表结构）。
4. 清理页面顶部注释里过期的分组描述（`knowledge_manage_page.dart:3-11`）。
5. 若管理页筛选维度因此变少，检查筛选 UI 是否还需要保留 chips 容器（无维度则隐藏整行）。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | 拍板为方案 A | 走查三个入口（画布 / 知识点管理页 / Agent 工具列表） | **三处均无分组相关入口**，状态一致，无"一半在" |
| 2 | 数据库中已有分组数据 | 执行方案 A | 数据**不被删除**，表结构保留（可恢复） |
| 3 | 同步 | 上传/拉取 | `kp_groups` 同步行为不变（不因隐藏 UI 而改动同步契约） |

### 风险与红线

- **RK-02（中）**：收敛下线可能误伤主理人自用习惯（如果你正在用管理页的分组筛选）。
  - 应对：**拍板前请主理人确认是否真在用**；表与数据保留，可随时恢复。
- 红线 #5（同步契约：隐藏 UI **不改**同步白名单与行映射）。

### 估算

## R-13 ｜ 死代码清理

### 一句话

把确认无人引用的孤儿页面、停用客户端、骗人的注释清掉，别让它们误导后续维护。

### 为什么要做

§13-A 列出的断头死代码会让新人（以及 AI 协作者）误判"这功能还在"，也会让静态扫描与代码阅读成本变高。其中 `extraction_service` 的注释**谎称"将走本地兜底"但实际直接失败**——属于文档漂移，比死代码更害人。

### 现状证据

| 项 | 事实 | 位置 |
|---|---|---|
| `lib/ui/extract_screen.dart` | 孤儿页面，**全仓无引用** | §13-A |
| `dify_client.dart` | 整段停用留注释（客户端实际只有 `llm_server_client.dart`） | §7.4 |
| `extraction_service.dart` | 日志「将走本地兜底」与"直接失败"**不符**，属过时注释 | §14 修正 #9 |
| `canvas_edges` 表 | **业务零引用死表**（连线实际走 `prerequisite_edges`） | §6.1、§13-A |
| `collapsed` 字段 | 仅表字段 + 同步搬运，UI 未接线 | §6.2、§13-A |
| `autoLinkByGroups` | 代码有、UI 未接 | §13-A（**已在 R-04 处置**） |
| `removeTableRow/Column` | block_actions 已实现，UI 未接 | §13-A（**在 BATCH-4 / R-12 接线，不是删除**） |

### 怎么做

1. 删除 `lib/ui/extract_screen.dart`（删除前 grep 确认零引用，全仓含测试）。
2. 删除 `dify_client.dart`（确认 `llm_server_client.dart` 不依赖它）。
3. 修正 `extraction_service.dart` 的过时注释：把「将走本地兜底」改成与实际一致的表述（**实际是直接失败**）。
4. `canvas_edges` 表：**本期只加注释标注"业务零引用，历史遗留"**，**不动表、不改同步**。理由：删表涉及迁移与同步契约变更，成本远大于收益，记入后续版本池单独立项。
5. `collapsed` 字段：**本期不动**。它没有害处（只是未接线的列），真要处置应与"节点折叠"功能一起做，记入后续版本池。
6. 删除后跑门禁与全量测试，确认无编译期/运行期引用断裂。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | 全仓 grep `extract_screen` / `DifyClient` | 删除后 | 零残留引用（含 test/ 与 import） |
| 2 | 阅读 `extraction_service.dart` 注释 | — | 注释与实际行为一致（不再声称本地兜底） |
| 3 | `canvas_edges` 标记 | — | 代码中有明确"死表/历史遗留"注释；**表结构与同步未变** |
| 4 | 门禁 | analyze + test | 0 错 0 警，测试全绿，用例数不减少 |

### 风险与红线

- **RK-06（低）**：删除误伤引用。应对：grep 全仓（含测试目录）+ 编译期保证。
- 红线 #5（同步契约）：本批**不改任何表结构与同步白名单**。
