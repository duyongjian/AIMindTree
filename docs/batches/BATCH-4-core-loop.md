## R-09 ｜ 老师模式状态机落地（最小版）

### 一句话

老师模式现在"能讲课"，但**难度从没存过、教学阶段恒为空**——把这两列真正用起来，让"再讲一次/追问"有策略差异。

### 为什么要做

老师模式是核心闭环的一环（写笔记 → 抽知识点 → 补前置 → **老师教** → 沉淀卡片 → 标记掌握）。但 `tutor_state` 恒写 `'{}'`、`difficulty` **从未写入任何值**（§8.1）——这是**隐性割裂**：界面上看不出问题，实际上"教学策略"这块是空的，用户换个难度、换个阶段，AI 给的东西完全一样。

### 现状证据

| 事实 | 位置 |
|---|---|
| `tutor_state` **恒写 `'{}'`**；`difficulty` **从未写入** → 状态机未落地 | §8.1、§13-A |
| 老师模式入口 3 个：画布点知识点 / 知识点管理页 / 笔记编辑器 | `teacher_page.dart`；`note_editor_page.dart:162` |
| 能力：单会话消息流 + 会话管理、首次自动讲解（T6）、「再讲一次」、追问（T5）、L2 历史快照注入 | §8.1 |
| 持 `kp:{id}` 锁，重复打开会 toast 挡回 | §8.1 |
| `ai_sessions` 表说明里写着"（chat/tutor + 老师模式状态机）" | §12 表 #15 |

### 怎么做（方案 A：落地最小状态机）

1. **`difficulty` 真实落库**：三档（建议：简单 / 适中 / 挑战），老师模式内提供切换入口，选择即写库，重开会话保持。
2. **`tutor_state` 记录阶段**：最小三态——`teaching`（讲解）/ `quizzing`（提问）/ `correcting`（纠正），外加轮次计数。写入时机：每次 AI 回合结束时更新。
3. **让策略有差异**：「再讲一次」「追问」调用 T6/T5 时，把**当前阶段 + 难度**注入 prompt（服务端 prompt 文件需同步调整）。差异可以是小的——比如讲解阶段偏阐述、提问阶段偏设问——**不做完整教学策略引擎**。
4. **会话恢复**：重新打开会话时读回 `difficulty` 与 `tutor_state`，UI 显示当前阶段。
5. 服务端：`llm_server/prompts/` 对应 prompt 增加难度/阶段占位；改完 `POST /v1/prompts/reload`。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | 进入老师模式并选择「挑战」难度 | 落库后关闭再重开 | 难度**保持**为「挑战」（不再是空值） |
| 2 | 处于讲解阶段 | 点「追问」 | 服务端收到的请求含阶段与难度（可日志/prompt 验证） |
| 3 | 切换难度 | 再讲一次 | 输出风格与之前有可观察差异（人工判定即可，不设量化阈值） |
| 4 | 数据库检查 | 会话结束后 | `tutor_state` **不再是 `{}`**；`difficulty` 有值 |

### 风险与红线

- **RK-05（中）**：工作量被低估（涉及服务端 prompt + App 两侧）。应对：**只做最小版**（难度 + 阶段字段 + prompt 注入），不做完整教学策略引擎；prompt 改动同步到 `llm_server/prompts/` 并 reload。
- 红线 #3（若改 Drift 表必跑 build_runner）、#5（同步契约：改动列需确认是否上行同步——`ai_sessions` 是同步表）。

### 估算

**2–3 人天（估算）**，含服务端 prompt 调整与联调。

## R-10 ｜ 游离知识点视图

### 一句话

把"提取出来了但还没进任何知识树"的知识点集中到一处，能看见、能批量入树、能删。

### 为什么要做

现在筛选维度里**没有「未加入任何知识树」**，反向入口只有逐条「加入知识树」，且提示"已经在树里了"**无法反查**（§5.4）。结果是：提取了一批知识点，忘了入树，它们就悄悄躺在库里，没有任何地方能统一找到——**这是内容黑洞**。

### 现状证据

| 事实 | 位置 |
|---|---|
| 筛选无「未加入任何知识树」维度；**无全局游离知识点视图** | §5.4、§6.4 |
| 反向入口只有逐条「加入知识树」，且提示"已经在树里了"无法反查 | §5.4 |
| 知识点是**全局独立资产**，可被多棵树共享 | §6.1 |
| 画布节点表 `canvas_nodes`（`target_type='kp'`）是"树成员关系" | §6.1；红线 #7 |

### 怎么做

1. **先定口径（写在代码注释里）**：游离 = `knowledge_points` 中**不在任何** `canvas_nodes`（`target_type='kp'`）里的知识点；**已软删的不算**（沿用 `deletedAt.isNull()`）。
2. 知识点管理页：筛选维度增加「未入树」（与类型/来源/掌握状态并列；注意与 R-06 分组结论保持一致，别把刚下线的分组 chips 又换回来）。
3. 新增「游离知识点」视图/页：列表展示全部游离点，支持**批量入树**（选目标树 → 落位）与**批量删除**（软删进回收站，复用现有软删路径）。
4. 批量入树落位：复用现有 `_autoPlaceNewPoints` 避让式落位（不要发明新算法）。
5. 空态：没有游离点时展示"当前没有游离知识点"而不是空白。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | 存在未入任何树的知识点 | 打开游离知识点视图 | **全部可见** |
| 2 | 选中若干游离点 | 批量入树（选定树） | 入树成功，画布上可见，位置不重叠（走避让落位） |
| 3 | 已软删的知识点 | 打开视图 | **不出现**（口径一致） |
| 4 | 没有任何游离点 | 打开视图 | 展示空态文案，不是白屏 |
| 5 | 筛选维度 | 查看 | 与 R-06 结论一致（分组若已下线，维度里不得出现分组） |

### 风险与红线

- 红线 #7（`canvas_nodes` 行 = 树成员关系，**不要当成纯视图记录删**）：批量入树是**新增**行，删除游离点是删 `knowledge_points`（软删），两者别搞混。
- 红线 #6（新增写库点必须触发刷新）：批量入树后画布与知识点页都要刷新。

### 估算

**1–1.5 人天（估算）**

## R-12 ｜ 编辑器低成本接线（删除表格行列 / 代码块语言选择器）

### 一句话

两个"底层能力已经写好、就差一个按钮"的功能：表格删除行列、代码块选语言。

### 为什么要做

这两项都在 §13-A 里被标为"已实现但 UI 未接"——**投入已经花了，只差最后一公里**。性价比极高。

### 现状证据

| 事实 | 位置 |
|---|---|
| `removeTableRow/Column`：**block_actions 已实现，UI 未接** | §13-A、§4.4 |
| 代码块语言选择器：**只显示不可选** | §4.4 |
| 块级原语全部集中在 `block_actions.dart`（纯 Dart） | 工作记忆 #27 |
| 工具栏 19 个按钮；代码块/表格/图片/分割线不支持行内格式 → 置灰但保留 tooltip | §4.2 |

### 怎么做

1. **删除表格行/列**：在表格单元格的右键菜单（或选中态工具栏）加「删除当前行」「删除当前列」，调用 `block_actions` 里**已有的** `removeTableRow` / `removeTableColumn`。
2. **代码块语言选择器**：代码块块头把"只显示"改成下拉选择（语言集合取项目已知列表；若无现成列表，用一组常见语言常量，标注为可配置）。
3. 两者改动都**必须保持 L1 字节直通**：改动后的块重造时不传 `source`（块类刻意不提供 `copyWith` 就是这个原因），未编辑块仍走原文直通。
4. 边界：删除表格最后一行/列时的行为要明确（是删除整个表格还是保留表头），写在验收里。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | 光标在表格某行 | 点「删除当前行」 | 该行移除，Markdown 表格语法**仍然合法**（行列对齐正确） |
| 2 | 光标在表格某列 | 点「删除当前列」 | 该列移除，其余列对齐正确 |
| 3 | 表格只剩一行/一列 | 执行删除 | 行为明确（删除整个表格 **或** 禁用入口并 tooltip 提示），无崩溃、无语法破损 |
| 4 | 代码块块头 | 选择语言 | 围栏标注（```lang）更新，且**只改该块**，其他块字节不变 |
| 5 | 打开笔记不编辑 | 保存 | `serialize(parse(md)) == md` 仍成立（L1 红线回归） |

### 风险与红线

- 红线 #1（L1 字节直通，验收 #5 覆盖）、#3（若新增块字段需跑 build_runner）。
- 边界行为（验收 #3）需**先定后做**，不要留给用户踩。

### 估算

**1 人天（估算）**
