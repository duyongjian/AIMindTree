## R-14 ｜ 同步增量拉取

### 一句话

现在每次拉取都是"全量拉"，改成只拉上次之后变化的部分。

### 为什么要做

`pull` **每次强制游标归零 → 实际是全量拉取**（§10.1）。数据量小时无感，数据一大每次同步都要搬全库，慢且浪费。

### 现状证据

| 事实 | 位置 |
|---|---|
| 拉取 = `pull`，**每次强制游标归零 → 实际是全量拉** | §10.1 |
| push 侧是分开的：`pushDrain`（增量排空）+ `pushAll`（全量快照） | §10.1 |
| LWW 规则、墓碑语义 | `sync_engine.dart:687-725` |
| 版本机制：服务端权威；**pull 侧不调版本**，直接把 `baseVersion` 落地成本地 version | §10.2 |
| EdgeOne KV 最终一致 ~60s → pull 自带 **65s lookback** 防丢更新 | §10.3 |

### 怎么做（要点，谨慎项）

1. 拉取时带上**本地各表 maxVersion** 作为游标，服务端只返回更新的行。
2. **必须保留 65s lookback**（EdgeOne KV 最终一致），否则会漏更新——这条不能为了性能砍掉。
3. 墓碑（deletedAt）也要按同样游标返回，否则删除无法同步。
4. **不改 LWW 判定规则**（`sync_engine.dart:687-725`），只改"取哪些行"。
5. 灰度建议：先在一个数据量小的表上验证，再全量切。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | 本地与服务器数据一致 | 执行拉取 | 返回行数为 0 或极小（不再全量搬运） |
| 2 | 服务器有 N 条新/改记录 | 执行拉取 | 恰好拉到这 N 条（不多不少） |
| 3 | 服务器有删除（墓碑） | 执行拉取 | 本地对应行被正确删除 |
| 4 | KV 最终一致窗口内（~60s） | 执行拉取 | **不漏更新**（65s lookback 仍生效） |
| 5 | 拉取后 | 比对 | 与全量拉取的结果**完全一致**（可用一次全量拉取做对照） |

### 风险与红线

- **高风险项**：涉及 LWW 与墓碑语义，改错会导致数据静默丢失。应对：验收 #5 必须与全量拉取结果对照；先小表后全量；保留"强制全量拉取"入口作为逃生舱。
- 红线 #5（同步契约）。

### 估算

**1–2 人天（估算）**

## R-15 ｜ 编辑器 undo-redo

### 一句话

给块级编辑器加撤销/重做。

### 为什么要做

现在编辑粒度是块内一行，**无 undo/redo**（§4.5）。误操作无法回退，是编辑器的硬伤。

### 现状证据

| 事实 | 位置 |
|---|---|
| 编辑粒度 = 块内一行，**无 undo/redo** | §4.5 第 1 条；§4.4「undo-redo ❌ 未实现」 |
| 块级原语集中在 `block_actions.dart`（纯 Dart） | 工作记忆 #27 |
| **L1 红线**：未编辑块 source 字节直通；块类**刻意不提供 copyWith** | §4.2；`block_model.dart:21-22, 273` |
| 每次变更全篇重算序列化 + 整列重建 | §4.5 第 2 条 |

### 怎么做

1. 做**块级快照栈**（不做字符级）：每次块级变更前后压栈 `NoteDoc` 快照（或最小化 diff）。
2. 栈深度设上限（建议 50 步，估算值），避免长文内存爆炸。
3. **关键约束**：撤销恢复的是"块内容与块序列"，**不得**借 undo 重建 `source`——否则会破坏 L1 字节直通（撤销一个未编辑块应恢复其原文，而不是重序列化的结果）。
4. 入口：工具栏按钮 + `Ctrl+Z / Ctrl+Shift+Z`（Windows）。
5. 与自动保存（R-01）协调：撤销后应触发保存（走同一路径）。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | 编辑了一个块 | 按 Ctrl+Z | 该块回到编辑前；其他块**字节不变** |
| 2 | 撤销后 | 按 Ctrl+Shift+Z | 重做回到撤销前状态 |
| 3 | 打开笔记不编辑，仅做"撤销"操作 | 撤销到初始态 | `serialize(parse(md)) == md` **仍成立**（L1 红线不被 undo 破坏） |
| 4 | 连续操作超过栈上限 | 继续撤销 | 到栈底即停止，不崩溃 |
| 5 | 撤销后 | 等待自动保存 | 撤销结果被正确保存（与 R-01 联动） |

### 风险与红线

- 红线 #1（L1 字节直通，验收 #3 覆盖）——**这是本条最大的坑**：undo 若重新序列化未编辑块，会把"打开就变脏"带回來。
- 内存：长文快照栈要设上限并实测。

### 估算

**2–3 人天（估算）**

## R-16 ｜ gridSize / showGrid UI 开关

### 一句话

网格吸附大小和网格线显示现在写死在代码里，给它们加个开关。

### 为什么要做

`gridSize`（0=关，20=开）与 `showGrid`（默认 false）目前**硬编码**，UI 无开关（§6.4）。用户想要网格线或改吸附精度时无从下手。

### 现状证据

| 事实 | 位置 |
|---|---|
| `gridSize` / `showGrid` **硬编码**，UI 无开关 | §6.4 |
| 网格吸附规则：`snapToGrid(v,g) = (v/g).round()*g`，缩放时自动加倍；`showGrid` 默认 false | 工作记忆 #18 |
| `LayoutConfig` 承载布局参数 | 工作记忆 #18 |

### 怎么做

1. 画布设置（可在工具栏菜单或设置面板）加两项：`显示网格线`（开关）、`网格大小`（0=关闭吸附 / 20 等档位）。
2. 值存本地偏好（**不进同步表**，避免改动同步契约——若确需跨设备，单独立项）。
3. 改动立即生效并显示 toast 反馈。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | 打开网格线开关 | 画布 | 网格线显示；关闭则隐藏 |
| 2 | 设置网格大小为 20 | 拖动节点 | 节点坐标吸附到 20 的倍数 |
| 3 | 设置为 0 | 拖动节点 | **不吸附**，自由落位 |
| 4 | 重启应用 | 查看 | 设置保持（本地偏好持久化生效） |
| 5 | 同步 | 上传/拉取 | **不因本功能改动同步表结构**（验收点：表结构 diff 为空） |

### 风险与红线

- 低风险。红线 #5（不改同步契约）。

### 估算

**0.5 人天（估算）**

## R-17 ｜ 图片 / 分割线浮层

### 一句话

插入图片和分割线后，能点它做替换 / 删除 / 改 alt。

### 为什么要做

现在图片/分割线**插入后无法替换、删除、改 alt**（§4.4）——插错了只能手动改 Markdown，等于这个功能只做了一半。

### 现状证据

| 事实 | 位置 |
|---|---|
| 图片 / 分割线的点击浮层（替换/删除/改 alt）**未实现** | §4.4 |
| `Divider / Image / Raw` 的 `textEditable = false` | §4.2 |
| 图片：`data_base64` 唯一权威存储，单图 **2MB 上限**，超限拒收且不压缩；同笔记 sha1 去重 | §4.3；`note_asset_repository.dart:38` |
| 保存时 `reconcileForNote` 回收孤儿附件 | §4.3 |

### 怎么做

1. 点击图片 / 分割线块 → 弹出浮层：替换 / 删除 / 改 alt（分割线无 alt，只给删除）。
2. 替换图片：走现有 `note_asset_repository` 插入路径，**复用 2MB 上限与 sha1 去重**，不要另写一套。
3. 删除：删块 + 触发孤儿附件回收（复用 `reconcileForNote`，不要手写清理）。
4. 浮层交互与已有块级操作保持一致（参考工具栏与现有块菜单风格）。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | 点击图片块 | 浮层出现 | 含「替换 / 删除 / 改 alt」三项 |
| 2 | 点「替换」选新图 | 确认 | 图片更新；**2MB 上限仍生效**，超限给出提示不崩溃 |
| 3 | 点「删除」 | 确认 | 块移除，孤儿附件被回收（附件表无残留孤儿行） |
| 4 | 点「改 alt」 | 输入保存 | Markdown 中 alt 更新，**其他块字节不变** |
| 5 | 点击分割线 | 浮层出现 | 只含「删除」（无 alt 项） |

### 风险与红线

- 红线 #1（L1 字节直通，验收 #4 覆盖）。
- 附件回收必须复用 `reconcileForNote`，避免产生新的孤儿数据。

### 估算

**1 人天（估算）**

## R-18 ｜ 未接线 AI 任务（7 个）逐个评估

### 一句话

有 7 个 AI 任务**只有 prompt 文件、没有任何调用**——逐个看一遍，有价值的接线，没价值的正式下线。

### 为什么要做

AI 任务共 T1–T15，其中 **9 个已接线、7 个未接线**（T2/T7/T9/T10/T11/T12/T13），且 **T13 与 T14 查重功能高度重叠**（§7.1）。这些"有 prompt 无调用"的资产既占维护成本，又让人误以为"有这个功能"。

### 现状证据

| 事实 | 位置 |
|---|---|
| 已接线 9 个：T1 / T3 / T4 / T5 / T5.detect / T6 / T8 / T14 / T15 | §7.1 |
| 未接线 7 个：T2 / T7 / T9 / T10 / T11 / T12 / T13 | §7.1 |
| **T13 相似度与 T14 查重高度重叠，属重复建设** | §7.1 注 |
| 任务定义 `ai/ai_task.dart:8-23`；服务端映射 `llm_server/prompts/index.yaml:6-23` | §7.1 |

### 怎么做

1. **本条只做评估（0.5 天）**，产出一张三列表：任务 / 它原本要做什么 / 结论（接线 / 下线 / 延后）。
2. 评估维度：① 是否服务核心闭环（写→抽→补→教→沉淀→掌握）；② 是否与已接线任务重叠；③ 是否有明确 UI 入口（没有入口的接线 = 新的断头功能）。
3. **T13 建议直接下线**（与 T14 重叠），其余逐个判断。
4. 结论为"下线"的：删除对应 prompt 文件引用或在 `index.yaml` 标注废弃，**不要留沉默的 prompt**。
5. 结论为"接线"的：单独立项（含 UI 入口设计），**不在本条内实现**。

### 验收标准（GWT）

| # | Given | When | Then |
|---|---|---|---|
| 1 | 7 个未接线任务 | 评估完成 | 产出评估表，每个任务都有明确结论（接线/下线/延后），**无"待定"** |
| 2 | T13 | 评估 | 结论明确（建议下线，与 T14 重叠） |
| 3 | 结论为"下线"的任务 | 处置 | prompt 不再被隐式引用，`index.yaml` 有废弃标注 |
| 4 | 结论为"接线"的任务 | 立项 | 每个都写明** UI 入口在哪**（无入口不得立项） |

### 风险与红线

- 无技术风险（纯评估）。红线：评估结论不能留"待定"，否则等于没做。

### 估算

**0.5 人天（仅评估，估算）**；接线另算。
