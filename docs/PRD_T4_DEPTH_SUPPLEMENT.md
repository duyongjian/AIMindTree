# 增量 PRD：选中知识点的递归前置链补完（T4 深度补充）

> 本文档为**增量 PRD**，仅描述本次变更，不重写 `docs/PRD.md` 已有能力。
> 关联文件：`scripts/dify_t4_gap_analysis.yaml`、`lib/ai/auto_graph_service.dart`、`lib/ai/ai_task_router.dart`、`lib/ai/ai_task.dart`、数据模型 `SuggestedPrerequisite`。

**项目信息**
- 项目名：`aimindtree_app`（AIMindTree）
- 技术栈：Flutter 3.47 / Dart / Drift(sqlite) + Dify 工作流（T1/T3/T4）
- 变更类型：语义变更 + 新交互入口（取代 `autoPrerequisites(treeId)` 的整树扫描行为）

---

## 1. 产品目标（一句话）
让用户点选知识树上的任意一个知识点，按所选"深度"递归补出"要理解它需要先懂什么"的前置知识链，仅以**建议**形态返回、绝不自动入库。

---

## 2. 用户故事
- **US1**：作为学习者，我想在画布上点选一个知识点并选择"高"深度，以便一次性看到从常识到该点的完整前置链，快速补齐基础。
- **US2**：作为学习者，我想选"中/低"深度，以便只补到初中/高中或大学入门级，不被过于基础的内容淹没。
- **US3**：作为学习者，我想用自然语言自定义深度（如"补到大学水平即可"），以便精确控制回溯程度。
- **US4**：作为离线用户，我想在无 AI / 未部署 Dify 时仍能用本地启发式得到近似的前置建议，以便随时随地梳理。

---

## 3. 需求池

### P0（Must have）
- **P0-1 选中入口**：画布节点支持点选/长按高亮，操作浮层提供"补充前置知识"动作；仅对单个已存在的 `KnowledgePoint` 触发（输入为该节点的 name/type/definition）。
- **P0-2 深度选择器**：发起时弹出 `低 / 中 / 高 / 自定义` 四选一；自定义展开自然语言输入框；选择结果随请求下发。
- **P0-3 T4 DSL 语义改造**：`dify_t4_gap_analysis.yaml` 由"输入 `existing_points` 扫描整树挖缺失词"改为"输入**单个选中知识点** + `depth` 指令 → 递归输出前置链 `gaps`"；输出项仍含 `name/type/definition/reason`，且不入库。
- **P0-4 锚点硬规则**：所有返回项仅构造 `SuggestedPrerequisite`，不得创建已验证 `KnowledgePoint`；UI 明示"仅为建议，需自行新建笔记"。
- **P0-5 T4 任务路由绑定（架构缺口）**：`AiTaskRouter` 为 `t4GapAnalysis` 绑定专属 provider（如专属 Dify 应用/key）；未命中 `ai_task_routes` 时**不得静默回落到 `fallback`（即 T1 应用）**，应报错明示，避免调错工作流。

### P1（Should have）
- **P1-1 T3 任务路由绑定（同根因）**：为 `t3Prerequisite` 绑定专属 provider，消除"T3 回落 T1"问题（与 P0-5 同一 `fallback` 缺陷）。
- **P1-2 本地启发式兜底**：AI 不可用 / 超时 / 未部署时，`autoPrerequisites` 改用本地规则（definition 关键词拆解 + 学段词典 + 深度层级）近似生成建议链，保证离线可用。
- **P1-3 递归控制**：T4 输出需限制链最大层数 / 每节点广度（可由 depth 推导上限），避免无限递归或超长响应。
- **P1-4 自定义指令透传**：自定义自由文本如何映射到 Dify 输入变量（新增 `depth_instruction` 变量或注入 prompt），需与 DSL 约定；本地兜底亦需能解析该自由文本。

### P2（Nice to have）
- **P2-1** 建议结果项"一键去新建笔记"引导（跳转到新建 `KnowledgePoint` 表单并预填 name/definition）。
- **P2-2** 建议链可视化：按层级缩进 / 可折叠展示，标注"链深度 N 层"。
- **P2-3** 同节点同深度建议结果短期缓存，避免重复调用。
- **P2-4** 绑定 UI：设置页提供 T3/T4 provider 绑定入口（替代 DB 直插 `ai_task_routes`）。

## 4. UI 设计稿

### (4.1) 画布选中节点 → 操作浮层
```
        ┌──────────────┐
        │  知识点节点  │◄── 单击 / 长按高亮
        └──────┬───────┘
               │ 弹出操作浮层
        ┌──────┴───────────┐
        │ ⭐ 标记为已掌握   │
        │ 🔗 连接前置       │
        │ ➕ 补充前置知识   │◄── 本次入口（仅对单节点）
        └──────────────────┘
```

### (4.2) 深度选择器（BottomSheet / Dialog）
```
   ┌─────────────────────────────┐
   │   补充前置知识到什么深度？   │
   │                             │
   │  (低)  (中)  (高)  (自定义) │  ← SegmentedControl 四选一
   │                             │
   │  低：最近一层直接相关前置    │
   │  中：中等基础（初中/高中）   │
   │  高：最基础（小学/常识）     │
   │                             │
   │  [ 自定义输入框 ] 补到大学水平│ ← 仅"自定义"展开
   │                             │
   │        [ 取消 ]  [ 生成 ]    │
   └─────────────────────────────┘
```

### (4.3) 建议结果弹窗（BottomSheet / Modal）
```
   ┌─────────────────────────────┐
   │  建议前置知识链（共 N 项）   │
   │  ⚠ 仅为建议，需自行新建笔记  │  ← 锚点硬规则提示
   │─────────────────────────────│
   │ ▸ 第1层（最接近该点）        │
   │    • 线性代数 [概念]         │
   │      定义：…  reason：理解XX │
   │ ▸ 第2层                      │
   │    • 向量空间 [概念] …       │
   │    • 矩阵    [概念] …        │
   │ ▸ 第3层（最基础）            │
   │    • 实数    [常识] …        │
   │─────────────────────────────│
   │  [ 知道了 ]  [ 去新建笔记➜ ] │
   └─────────────────────────────┘
```

## 5. 待确认问题（Open Questions）
1. **学段契约**：低/中/高 与"学段"语义是否以本文为准？是否需要在 DSL 中把 depth 量化为 `1/2/3` 级或学段枚举，供 T4 与本地兜底共用同一契约？
2. **自定义透传**：自定义自然语言如何传给 Dify T4——新增输入变量 `depth_instruction` 还是拼接进主 prompt？本地兜底又如何解析这段自由文本？
3. **本地兜底近似**：无 AI 时，本地兜底如何按 低/中/高 近似"回溯深度"？是否依赖一张"学段→前置关键词"的本地词典，由深度决定下钻层数？
4. **递归上限**：T4 前置链的"最大层数 / 每节点分支数"上限如何设定才能既完整又不致响应过长？是否由 depth 直接推导？
5. **旧行为处置**：现有 `AutoGraphService.autoPrerequisites(treeId)` 整树扫描行为，本次是直接删除/废弃，还是保留为内部子函数被新入口（单节点 + 深度）调用？
