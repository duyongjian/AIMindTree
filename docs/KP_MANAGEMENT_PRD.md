## 1. 产品目标与本次范围

### 1.1 一句话 TL;DR

> 修复 5 个已核实的 P0 缺陷（老师模式黑屏崩溃 / 启动脚本中文乱码 / 删除后仍可见 / AI 状态误报未连接 / 提取后管理后台无日志无任务）；新增**知识点管理页**（列表 + 增删改查 + 追问 + 拉入知识树）；把提取入口从底部 Tab 移入**笔记详情页**；并将数据关系从「笔记直连知识树」重构为「**笔记 → 提取 → 知识点 → 关联 → 知识树**」（知识点可无来源笔记）。

### 1.2 In Scope（本次做）

- P0：5 项缺陷修复（崩溃 / 乱码 / 删除残留 / AI 状态 / 后台可观测性）。
- P1：知识点管理页；批量删除笔记；底部 Tab 去「提取」并在笔记详情页提供新提取入口；知识树「添加知识点」（从管理页拉入）；笔记详情展示其提取的知识点并可跳转详情；追问复用老师模式页。
- P2：关系重构的数据迁移与兼容策略评估、同步影响评估。

### 1.3 Out of Scope（本次不做）

- 用户诉求第 8 条「同步功能干啥用的」——由主理人在最终回复中直接解答，PRD 不覆盖（但其对同步表的影响在 P2-2 评估）。
- T7 苏格拉底引导的页面化（当前无页面承载，本期追问只接 T5/T6）。
- 知识点回收站 / 删除恢复。
- `source_note_id` 可空化的 Drift 表重建迁移（P2 仅出评估与排期，不在本期实施）。
- llm_server 管理后台的改版（仅修复「日志/任务可见性」所需的最小范围）。
- iOS / Android / Web 端适配排期。

## 2. 用户故事

角色：**知识管理者**（陈默式用户：笔记量大、以 AI 提取为主要生产方式、需要人工修剪知识结构）。

| # | 用户故事 |
| --- | --- |
| US-1 | 作为知识管理者，我想在一个页面看到全部知识点的列表（名称/类型/来源/掌握状态），以便俯瞰和检索我的知识资产。 |
| US-2 | 作为知识管理者，我想手动新建、编辑、删除知识点，以便修正 AI 提取的错漏、补充 AI 没抽到的概念。 |
| US-3 | 作为知识管理者，我想对任意知识点直接发起追问/听讲解，以便在管理场景中即时解决疑惑。 |
| US-4 | 作为知识管理者，我想把知识点拉进指定的知识树，以便按我自己的体系组织知识，而不是只按笔记归属。 |
| US-5 | 作为知识管理者，我想批量删除笔记，以便快速清理已归档的原始材料。 |
| US-6 | 作为知识管理者，我想在笔记详情页看到它提取出的知识点并点击进入详情，以便回溯「这个知识点从哪来」。 |
| US-7 | 作为知识管理者，我想让删掉的知识点在所有界面都不再出现，以便信任「删除」这个操作。 |
| US-8 | 作为知识管理者，我想在启动脚本窗口里看到可读的中文提示，以便判断服务是否正常拉起。 |

## 3. 需求池

优先级定义：**P0 = Must have（缺陷修复，不修则核心流程不可用/不可信）；P1 = Should have（本期功能）；P2 = Nice to have / 后续评估**。

### 3.1 P0 缺陷修复

#### P0-1 老师模式黑屏崩溃（用户诉求 11）

| 项 | 内容 |
| --- | --- |
| 现象 | 知识树「补充前置」走到最后一步点「补充进树」后黑屏；控制台报 `setState() or markNeedsBuild() called during build`（JobTray，经 `TeacherPage.initState → AiJobService.holdInteractive → _notify → revision.value++` 触发）。 |
| 根因（已核实） | `lib/ai/ai_job_service.dart:360` `holdInteractive()` 内同步调 `_notify()`（:511-513 `revision.value++`）；`lib/ui/job_tray.dart:51-53` 的监听器 `_onRevision()` 直接 `setState`。当 `holdInteractive` 发生在 build 阶段（`TeacherPage.initState`，见 `lib/features/teacher/teacher_page.dart:66-76`），监听器在 build 期间 setState → 框架断言 → 黑屏。**任何 push TeacherPage 的入口都会触发。** |
| 修复方向（供工程师） | 通知改为构建安全方式（如 post-frame / microtask 延后通知，或监听侧防重入）；不得删除托盘对交互会话的可见性。 |
| 验收标准 | ① 从知识树节点、笔记详情知识点、管理页追问三个入口进入老师模式，均不黑屏、无框架断言；② JobTray 仍实时反映交互会话（`kp:{id}` 锁徽标、计时、「正在生成讲解…」等文案联动）；③ 回归 Dart 门禁 0/0/0 与 flutter test 213/213；④ 新增针对「build 期间通知监听器」的回归测试（形态由工程师定，须可失败于旧实现）。 |

#### P0-2 启动脚本中文乱码（用户诉求 1）

| 项 | 内容 |
| --- | --- |
| 现象 | `scripts/run_llm_server.bat` 与 `scripts/run_windows_fast.bat`（或 `run_windows.bat`）启动窗口顶头的 echo 中文乱码。 |
| 根因（已核实） | 3 个 bat 均为 UTF-8 无 BOM + CRLF（行尾无误）；CMD 默认代码页 936（GBK）解释 UTF-8 字节 → 乱码。 |
| 修复方向（供工程师） | 脚本顶部加 `chcp 65001 >nul`（不加 BOM、保持 CRLF，避免影响既有逻辑）。 |
| 验收标准 | ① 三个脚本启动后，窗口内所有中文（提示 / 进度 / 错误）可读；② 脚本既有功能不变（Ollama 检查、模型 create、清代理、参数解析）；③ `git diff` 确认仅新增代码页切换行（+必要注释）。 |

#### P0-3 删除后仍可见（用户诉求 4）

| 项 | 内容 |
| --- | --- |
| 现象 | 用户删了知识点后，仍在某处看到（原话：「我把知识点都删了为什么本地库还是能看到」）。 |
| 根因 | **具体复现路径待工程师定位**（缺用户操作步骤：在哪个界面删、在哪里看到）。已核实的两个隐患：① `lib/data/repositories/knowledge_repository.dart:469-496` 的 `allKnowledgePoints / pointsForNote / pointsByIds` **均未过滤 `deleted_at`**，违反软删铁律——本期引入知识点软删除后即成真 bug；② 删笔记选「保留知识点」时，知识点按设计保留为独立资产并留在树里（`lib/main.dart:333-366` 删除回执已有提示），与用户预期可能存在落差。 |
| 修复方向（供工程师） | 按 §4.1 删除语义矩阵统一行为；全量审计所有读路径补 `deleted_at isNull()`（列表 / 画布 / 详情 / AI 助手工具 / 任何 pointsByIds 调用方）。 |
| 验收标准 | ① 全库审计清单（工程师产出）：每个 KP / 边 / 成员 / 掌握状态查询点均有软删过滤或有等价设计；② 删除语义矩阵每条可实现、可验证（见 §6）；③ 用户复现场景（待用户补步骤后）修复并经用户确认；④ 回归 213 测试。 |

#### P0-4 AI 服务状态误报「未连接」（用户诉求 7）

| 项 | 内容 |
| --- | --- |
| 现象 | 设置页 AI 服务状态显示「未连接」。 |
| 已核实事实 | `ai_providers` 有 1 条 llm_server 行（enabled=1, is_default=1, `http://127.0.0.1:8787`）；状态区探活走 `lib/features/settings/ai_service_status_section.dart:107-115` `testLlmServer(baseUrl, 3s)`；另有 3 条 enabled=1 的旧 Dify 行（is_default=0，bootstrap 打 warning 跳过，不影响提取）。 |
| 根因 | **待工程师定位。** 假设清单：a) llm_server 当时未运行；b) App 进程继承本机系统代理 `127.0.0.1:44166`，探活 127.0.0.1 被代理拦截（bat 脚本清空代理变量正是为此，从 IDE 直接 run 时无此环境）；c) 探活端点 / 3s 超时过短；d) 多条 enabled 行干扰默认行选择。 |
| 验收标准 | ① llm_server 运行中时，状态页 3 秒内显示「已连接」并展示后端 / 模型 / 地址；② 未运行时显示「未连接」+ 人话原因（如「服务未启动，请先运行 scripts\run_llm_server.bat」）；③ 点「重新连接」可从断到连恢复；④ App 内对 127.0.0.1 的探活不受本机代理环境变量影响（客户端直连或禁代理）；⑤ 旧 Dify 行不干扰默认行选择与状态判定。 |

#### P0-5 提取后管理后台无日志、无任务（用户诉求 2）

| 项 | 内容 |
| --- | --- |
| 现象 | 提取知识点后，llm_server 管理后台 M7「运行日志」/ M10「任务队列」面板均无记录。 |
| 已核实事实 | M10 数据源为 `GET /v1/jobs`（`llm_server/static/app.js:17`、`views-d.js`），**只有队列路径产生 job**；M7 数据源为进程内环形日志缓冲（`llm_server/core/logbuf.py`，挂 root logger，默认 INFO 级）；App 提取有两条路径：队列路径（`jobs.submit`，`lib/ui/extract_screen.dart:78-102`）与同步兜底路径（`ai.run` → `POST /v1/chat`，:110-113）。 |
| 根因 | **待工程师定位。** 假设清单：a) 本次提取走了同步兜底（`kAiJobQueueEnabled=false` 或 submit 抛异常回落），不进 `/v1/jobs`；b) `/v1/chat` 路径在非 verbose 时只打 debug 级摘要（`core/logging.py` `dump()`），INFO 缓冲里看不到；c) 用户查看的管理后台与 App 实际连接的服务不是同一实例 / 端口；d) 管理后台视图刷新问题。 |
| 验收标准 | ① 队列路径提取：M10 出现该 job 且 `queued→running→done` 全状态可见，M7 有对应 INFO 日志；② 同步兜底路径提取：M7 至少有 1 条 INFO 日志记录该次调用（任务码 / 耗时 / 结果概要）；③ 管理后台两面板数据与 App 托盘一致；④ 服务未启动时 App 提取失败给出人话提示，而非静默无记录。 |

### 3.3 P2（关系重构的迁移与兼容、同步影响评估）

#### P2-1 关系重构的数据迁移与兼容策略（用户诉求 9）

| 项 | 内容 |
| --- | --- |
| 范围 | ① 目标关系：笔记 →（提取）→ 知识点 →（关联）→ 知识树；知识点不再必须关联笔记；笔记树（canvas.id == noteId）历史数据兼容保留。② 本期落地「空串哨兵」方案（§4.3），零 schema 变更。③ 「`source_note_id` 可空化」的 Drift 表重建迁移仅出评估：需 `schemaVersion` +1、手工复刻 `.g.dart`（沙箱禁跑 build_runner）、SQLite 12 步表重建、旧库无损验证。 |
| 兼容策略 | 现有 24 行 KP 均有真实 `source_note_id`，哨兵方案对旧数据零影响；手动新建知识点默认不属于任何树；同步 payload 中空串按「无来源」处理。 |

## 4. 关键设计决策（产品拍板）

### 4.1 删除语义矩阵（权威定义）

统一前提：**软删铁律**——所有列表查询必须 `deleted_at isNull()`（P0-3 落地）；删除后任何界面不得复现已删实体。

| 操作 | 笔记本体 | 其提取的知识点 | 树成员关系（canvas_nodes） | 前置边（prerequisite_edges） | 掌握记录 | 可见性预期 |
| --- | --- | --- | --- | --- | --- | --- |
| 删笔记 · 选「同时删除知识点」 | 软删除 | **软删除**（tombstone，version++） | 涉及行硬删除（沿现有先例） | **软删除** | 保留（append-only 历史，不回显） | 全部界面消失 |
| 删笔记 · 选「保留知识点」 | 软删除 | 保留，标记「无来源笔记」 | 仅用户勾选的树解除；未勾选保留 | 保留 | 保留 | 管理页 / 未解绑树仍可见（**设计使然，弹窗须明示**） |
| 删单个知识点（本期新增） | 不受影响 | **软删除** | 该 KP 在所有树的成员行硬删除 | 涉及边**软删除** | 保留 | 全部界面消失 |
| 删知识树 · 不删知识点 | — | 保留 | 该树成员行硬删除 | 保留 | 保留 | 树消失，知识点在管理页仍可见 |
| 删知识树 · 同时删知识点 | — | **软删除** | 该树成员行硬删除 | 涉及边**软删除** | 保留 | 知识点全部界面消失 |

补充规则：
- 成员行硬删除 / 边与 KP 软删除的不对称，是为控制同步风险（KP tombstone 是删除的权威信号；成员行硬删除沿用 `deleteNote/deleteTree` 现有先例，技术债登记，P2-2 评估）。
- 「删了还能看到」的预期行为定义：删除成功 → 下一次任何查询起，该 KP 不出现在管理列表 / 知识树画布 / 笔记详情知识点区 / AI 助手检索结果 / 老师模式入口中。本期**不提供**回收站与恢复（P2 候选）。
- 删知识点弹窗须预览影响面：所在知识树列表、涉及前置边数量（沿用删笔记弹窗的信息结构）。

### 4.2 锚点铁律豁免规则（手动知识点）

| 来源 | origin 值 | 锚点校验 | source_quote | source_start/end | source_note_id |
| --- | --- | --- | --- | --- | --- |
| AI 提取 | `ai_extract` | **必须逐字命中原文，否则剔除**（铁律保留） | 必填 | 实测区间 | 必有 |
| 手动新建 | `user_manual` | **豁免** | 允许空串 | `-1` 哨兵 | 可为空（见 §4.3） |
| 老师模式沉淀（预留） | `tutor` | 豁免 | 允许空串 | `-1` 哨兵 | 可为空 |

理由：铁律的目的是防 AI 幻觉；用户手动输入的内容本身就是权威来源，要求 quote 自证没有意义。豁免仅在 Repository 层按 `origin` 判定，UI 不参与。

### 4.3 `source_note_id` NOT NULL 的迁移策略

**决策：本期用「空串哨兵 `''`」，可空化列为 P2 评估项。**

| 维度 | 空串哨兵（采纳） | 可空化（P2 评估） |
| --- | --- | --- |
| schema 变更 | 无 | Drift 表重建 + `.g.dart` 手工复刻（沙箱禁跑 build_runner，成本高、易错） |
| 旧数据影响 | 零（现有 24 行均为真实 ULID） | 迁移期旧库只读风险 |
| 同步影响 | 无（string 列语义内变化） | 迁移窗口期跨设备同步需特殊处理 |
| 查询改造成本 | `sourceNoteId == ''` 判定收敛为 Repository 辅助方法 | 天然可空 |

风险缓解：哨兵常量收口在 Repository 一处；§11「禁止 UI 直写表」铁律保证所有写入口径可控；笔记 ID 为 ULID，永不与 `''` 冲突。

### 4.4 提取入口落点

**决策：落到笔记编辑器页（`NoteEditorPage`）顶部**——AppBar 动作图标 + 正文区主按钮「提取知识点」。

- 理由：提取的本质动作是「对这篇笔记做提取」，入口与操作对象同页最自然；Tab 位让给知识点管理（见下），信息架构从「工具导向」转为「资产导向」。
- AI 助手页现有的「提取 → 入树 → 自动连线」链（`ExtractIntoTreeChain`）保留不动——它是 AI 对话式能力，不是被移除的 Tab。
- 「提取」Tab 原位替换为「知识点」Tab（4 Tab 方案：笔记 / 知识树 / 设置 / AI 助手；5 Tab 方案见待确认 Q4）。

### 4.5 追问复用哪个 AI 任务

**决策：复用 `TeacherPage`（T5 追问 + T6 讲解二合一页）**，见 `lib/features/teacher/teacher_page.dart` 头部文档注释——该页本就是「讲解 + 追问」结构，底部浮层入口叫「AI 讲解 / 追问」。

- T7 苏格拉底引导是独立状态机、当前无页面承载，本期不接（Out of Scope）。
- 前置依赖：P0-1 黑屏修复（任何 push TeacherPage 都会触发）。

### 4.6 知识点详情页形态

**决策：不新建页面，复用 `TeacherPage` 作为「知识点详情 + 老师模式」二合一页**，P1 增强其信息头：

- 展示：名称、类型徽标、定义、来源（笔记标题可跳转编辑器 / 「手动」/「无来源笔记」）、掌握状态（可设置，走 `setMastery`，保留级联降级）。
- 动作：编辑、删除（影响面预览，见 §4.1）、加入知识树、追问 / 讲解 Tab。
- 理由：TeacherPage 已按 KP 维度构建（会话、资源锁、托盘联动），知识树节点点击（`onKpTap`）与管理页追问入口可自然收敛到同一落地页，避免第二套近似页面。代价：进入详情即自动生成一次讲解（T6）——这是产品核心体验，接受。
